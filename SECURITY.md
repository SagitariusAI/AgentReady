# Security Policy

## Supported versions

Only the current default branch and the most recent published release are considered for security fixes. This is not
a promise that a fix, response, update, release, or continued support will be provided.

## Report a vulnerability privately

Do not disclose an unpatched vulnerability, exploit, credential, token, private endpoint, personal data,
third-party-owned repository content, or other sensitive evidence in a public issue.

Use the repository's **Security** tab and select **Report a vulnerability** to start a private GitHub security
advisory. Include only the minimum information needed to reproduce and assess the issue:

- affected version or commit;
- affected component and configuration;
- reproduction steps or a minimal proof of concept;
- potential impact;
- suggested mitigation, if known; and
- a safe way to request any additional sensitive evidence.

If private vulnerability reporting is unavailable, open a public issue containing no sensitive or exploitable detail
and request a private reporting channel.

## Research and testing rules

Use synthetic data and systems you own or are explicitly authorized to test. Do not access, alter, interrupt, or
exfiltrate another person's systems or data. Do not include live secrets in a report. Preserve relevant evidence
without expanding the impact.

## No security promise

Publication of this policy, a response, a scan, a passing gate, or a released fix does not promise that AgentReady is
secure, vulnerability-free, compatible, supported, or suitable for any use. Users remain responsible for threat
modeling, access control, dependency review, testing, monitoring, backups, recovery, and timely updates.
